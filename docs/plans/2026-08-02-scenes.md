# L2 scenes and layered recall — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give recall a layer between a single message and a standing rule, and prove with `cml eval` that it retrieves better.

**Architecture:** One `scene` row per session with five or more rows, written by the existing curator path under a new rubric. Scenes are a **re-ranking signal over `mem` rowids**, not a replacement result — so `cml eval` keeps measuring the same thing it measured at 19.7% and the comparison stays honest. The scene headline is presentation, added in `recall()` only after the gate passes.

**Tech Stack:** C++20, sqlite3 FTS5, simdjson, CMake, the DeepSeek endpoint already configured at `distill.cpp:29`.

**Spec:** `docs/design/layering-and-offload.md`

## Global Constraints

- **300 lines per source file, hard.** `recall.cpp` is already **306** — Task 1 exists because of it.
- `-Wall -Wextra -Wpedantic -Werror`.
- Hook subcommands exit 0 on every path (`main.cpp:60-61`).
- FTS5 table definitions must never drift — the tokenizer is stored inside the definition, and a mismatch silently rebuilds the index (`db.cpp:133-136`).
- Curator calls cost real money on a personal key. Calibrate on 20 before running 75.
- Build: `cmake -S cpp -B cpp/build && cmake --build cpp/build -j2` · Test: `./cpp/build/cml_selftest`

## Spec refinement made during planning

The spec says the gate is "`cml eval` recall@3 must exceed 19.7%". Planning found that a scene occupying one of the three injected lines would reduce the matchable slots from 3 to 2 and depress the metric regardless of quality. Scenes are therefore implemented as a re-rank over the existing rowid space (Task 6), which keeps the gate valid. Update the spec's Success criteria when Task 7 records the result.

### Task 6: Scenes as a re-ranking signal

The scene must not consume an injected line during evaluation, or `cml eval` measures the format change rather than the retrieval change. It re-ranks `mem` rowids instead.

**Files:**
- Modify: `cpp/src/recall/retrieve.cpp`, `cpp/src/recall.hpp` (add the option)
- Modify: `cpp/src/selftest/ports.cpp`

**Interfaces:**
- Consumes: `RetrieveOpts` as it exists today.
- Produces:
  - `RetrieveOpts.scene_first` — `bool`, default `false`, so every existing caller is unchanged.
  - ```cpp
    // Pure, so the load-bearing half is assertable without a database (ports.cpp has none).
    // Stable-partition `ranked` so rowids whose session won a scene match come first.
    // Order within each group is untouched: this REORDERS, it never admits a row the
    // gates rejected nor drops one they passed.
    void scene_partition(std::vector<std::int64_t>& ranked,
                         const std::unordered_map<std::int64_t, std::string>& session_of,
                         const std::unordered_set<std::string>& winners);
    ```

- [ ] **Step 1: Write the failing test**

```cpp
void test_scene_partition_reorders_without_adding_or_losing() {
    std::vector<std::int64_t> ranked = {10, 11, 12, 13, 14};
    const std::unordered_map<std::int64_t, std::string> session_of = {
        {10, "a"}, {11, "b"}, {12, "a"}, {13, "c"}, {14, "b"}};
    const std::unordered_set<std::string> winners = {"b"};

    cml::scene_partition(ranked, session_of, winners);

    ok(ranked.size() == 5, "no row added, no row lost");
    ok(ranked[0] == 11 && ranked[1] == 14, "the winning session's rows come first");
    ok(ranked[2] == 10 && ranked[3] == 12 && ranked[4] == 13,
       "and the losers keep their original BM25 order — stable, not sorted");

    // A rowid the map has never heard of must not be dropped or crash the partition.
    std::vector<std::int64_t> orphan = {99};
    cml::scene_partition(orphan, session_of, winners);
    ok(orphan.size() == 1 && orphan[0] == 99, "an unmapped rowid survives untouched");

    // No scene matched: the ranking must come out exactly as it went in.
    std::vector<std::int64_t> untouched = {10, 11, 12};
    const std::vector<std::int64_t> before = untouched;
    cml::scene_partition(untouched, session_of, {});
    ok(untouched == before, "no winners means no change at all");
}
```

Register it in `suite_ports()`.

- [ ] **Step 2: Run to verify it fails**

Run: `cmake --build cpp/build -j2`
Expected: FAIL — `scene_partition` undeclared.

- [ ] **Step 3: Implement**

`scene_partition` is `std::stable_partition` over a predicate that looks the rowid's session up in `session_of` and tests membership in `winners`; an absent rowid is a non-winner.

Then in `retrieve()`, when `opts.scene_first` is set: query `scene_fts` with the same OR-query through the same rarity gate, collect the winning sessions, look up the session of each ranked rowid, and call `scene_partition`. Gates, limit and dedupe all stay exactly where they are and run afterwards, unchanged.
